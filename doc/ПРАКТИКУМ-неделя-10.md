## Как работать с задачами

1. Читаешь код.
2. Отвечаешь вслух (или в чат) — **что выведет консоль и в каком порядке**.

## Блок 1 — Event Loop и Call Stack

### Задача 1

```js
console.log('start');
setTimeout(() => console.log('timeout'), 0);
console.log('end');
```

<details>
<summary>Ответ</summary>

```
start
end
timeout
```

Колбэк `setTimeout` помещается в очередь макрозадач. Стек вызовов должен полностью очиститься, прежде чем Event Loop возьмёт следующую макрозадачу.

</details>

---

### Задача 2

```js
console.log('1');
setTimeout(() => {
  console.log('2');
  setTimeout(() => console.log('3'), 0);
  console.log('4');
}, 0);
console.log('5');
```

<details>
<summary>Ответ</summary>

```
1
5
2
4
3
```

Внешний таймер — первая макрозадача: выводит `2`, планирует ещё одну, выводит `4`. Вложенный таймер — вторая макрозадача: `3`.

</details>

---

### Задача 3

```js
setTimeout(() => console.log('a'), 100);
setTimeout(() => console.log('b'), 0);
setTimeout(() => console.log('c'), 50);
console.log('d');
```

<details>
<summary>Ответ</summary>

```
d
b
c
a
```

Синхронный код — первым. Таймеры выполняются в порядке задержки: 0 мс → 50 мс → 100 мс.

</details>

---

### Задача 4

```js
for (var i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);
}
```

<details>
<summary>Ответ</summary>

```
3
3
3
```

`var` — функциональная область видимости, все три колбэка захватывают **одну и ту же** переменную `i`. К моменту выполнения таймеров цикл завершён, `i === 3`. С `let` (блочная область) вывелось бы `0 1 2`.

</details>

## Блок 2 — Микрозадачи и макрозадачи

### Задача 5

```js
console.log('1');
Promise.resolve().then(() => console.log('2'));
setTimeout(() => console.log('3'), 0);
console.log('4');
```

<details>
<summary>Ответ</summary>

```
1
4
2
3
```

Порядок: синхронный код → очередь микрозадач → очередь макрозадач. `Promise.then` — микрозадача, `setTimeout` — макрозадача.

</details>

---

### Задача 6

```js
console.log('start');
Promise.resolve()
  .then(() => console.log('micro 1'))
  .then(() => console.log('micro 2'));
setTimeout(() => console.log('macro'), 0);
Promise.resolve().then(() => console.log('micro 3'));
console.log('end');
```

<details>
<summary>Ответ</summary>

```
start
end
micro 1
micro 3
micro 2
macro
```

После синхронного кода в очереди: `[micro 1, micro 3]`. Запуск `micro 1` добавляет `micro 2` в конец → `[micro 3, micro 2]`. Только после полного опустошения очереди микрозадач запускается `macro`.

</details>

---

### Задача 7

```js
setTimeout(() => console.log('timeout'), 0);
queueMicrotask(() => console.log('microtask'));
console.log('sync');
```

<details>
<summary>Ответ</summary>

```
sync
microtask
timeout
```

`queueMicrotask` — явная постановка в очередь микрозадач. Как и `Promise.then`, выполняется до следующей макрозадачи.

</details>

## Блок 3 — Promise: базовое

### Задача 8

```js
Promise.resolve(1)
  .then(x => x + 1)
  .then(x => x * 2)
  .then(console.log);
```

<details>
<summary>Ответ</summary>

```
4
```

Цепочка `.then`: каждый обработчик получает возвращённое значение предыдущего. `1 → 2 → 4`.

</details>

---

### Задача 9

```js
Promise.resolve('a')
  .then(x => Promise.resolve(x + 'b'))
  .then(x => x + 'c')
  .then(console.log);
```

<details>
<summary>Ответ</summary>

```
abc
```

Если `.then` возвращает Promise, следующий обработчик получает **разрешённое значение** этого Promise, а не сам объект Promise.

</details>

---

### Задача 10

```js
Promise.reject('oops')
  .then(x => console.log('then:', x))
  .catch(e => console.log('catch:', e));
```

<details>
<summary>Ответ</summary>

```
catch: oops
```

`.then` пропускается при отклонённом Promise — управление передаётся к ближайшему `.catch`.

</details>

---

### Задача 11

```js
Promise.reject('error')
  .catch(e => 'recovered: ' + e)
  .then(x => console.log(x));
```

<details>
<summary>Ответ</summary>

```
recovered: error
```

`.catch` возвращает новый **разрешённый** Promise (если не бросает исключение). Цепочка продолжается: следующий `.then` получает возвращённое из `.catch` значение.

</details>

---

### Задача 12

```js
console.log('1');
new Promise((resolve) => {
  console.log('2');
  resolve('done');
  console.log('3');
}).then(x => console.log(x));
console.log('4');
```

<details>
<summary>Ответ</summary>

```
1
2
3
4
done
```

Функция-экзекутор `new Promise(fn)` выполняется **синхронно**. `resolve()` лишь помечает Promise как выполненный — обработчик `.then` ставится в очередь микрозадач позже.

</details>

## Блок 4 — async / await

### Задача 13

```js
async function greet() {
  return 'hello';
}
const result = greet();
console.log(result instanceof Promise);
result.then(console.log);
```

<details>
<summary>Ответ</summary>

```
true
hello
```

`async`-функция **всегда** возвращает Promise. `return 'hello'` — сахар над `Promise.resolve('hello')`.

</details>

---

### Задача 14

```js
async function run() {
  console.log('a');
  const x = await Promise.resolve('b');
  console.log(x);
  console.log('c');
}
console.log('start');
run();
console.log('end');
```

<details>
<summary>Ответ</summary>

```
start
a
end
b
c
```

`await` приостанавливает **только текущую async-функцию**, не весь поток. Управление возвращается к вызывающему коду, а продолжение после `await` ставится в очередь микрозадач.

</details>

---

### Задача 15

```js
async function load() {
  console.log('loading');
  const data = await Promise.resolve(42);
  console.log('data:', data);
  return data;
}
console.log('before');
load().then(v => console.log('result:', v));
console.log('after');
```

<details>
<summary>Ответ</summary>

```
before
loading
after
data: 42
result: 42
```

`load()` запускается синхронно до `await`. После `await` — микрозадача. `.then` на возвращённом Promise — ещё одна микрозадача после завершения `load`.

</details>

---

### Задача 16

```js
async function run() {
  console.log('start');
  await null;
  console.log('after await');
}
run();
console.log('sync after run()');
```

<details>
<summary>Ответ</summary>

```
start
sync after run()
after await
```

`await null` эквивалентен `await Promise.resolve(null)` — приостанавливает функцию, даже если значение уже известно.

</details>

---

### Задача 17

```js
async function run() {
  const a = await Promise.resolve(1);
  const b = await Promise.resolve(2);
  const c = await Promise.resolve(3);
  console.log(a + b + c);
}
run();
console.log('sync');
```

<details>
<summary>Ответ</summary>

```
sync
6
```

Каждый `await` — отдельная микрозадача. Синхронный код после `run()` выполнится раньше, чем функция доберётся до `console.log`.

</details>

## Блок 5 — Обработка ошибок

### Задача 18

```js
async function risky() {
  throw new Error('boom');
}
async function run() {
  try {
    await risky();
    console.log('ok');
  } catch (e) {
    console.log('caught:', e.message);
  }
}
run();
```

<details>
<summary>Ответ</summary>

```
caught: boom
```

`throw` внутри `async`-функции превращается в отклонённый Promise. `try/catch` с `await` перехватывает его.

</details>

---

### Задача 19

```js
async function run() {
  const result = await Promise.reject('fail').catch(e => 'fallback');
  console.log(result);
}
run();
```

<details>
<summary>Ответ</summary>

```
fallback
```

`.catch` перехватывает отклонение и возвращает `'fallback'` — получается разрешённый Promise. `await` разворачивает его в строку.

</details>

---

### Задача 20

```js
Promise.resolve('ok')
  .then(x => { throw new Error('oops'); })
  .then(x => console.log('never'))
  .catch(e => console.log('error:', e.message));
```

<details>
<summary>Ответ</summary>

```
error: oops
```

Исключение внутри `.then` отклоняет возвращаемый Promise. Следующий `.then` пропускается, управление прыгает к `.catch`.

</details>

---

### Задача 21

```js
async function run() {
  try {
    const x = await Promise.resolve(10);
    console.log('got:', x);
    await Promise.reject(new Error('bad'));
    console.log('unreachable');
  } catch (e) {
    console.log('error:', e.message);
  }
  console.log('done');
}
run();
```

<details>
<summary>Ответ</summary>

```
got: 10
error: bad
done
```

`try/catch` оборачивает несколько `await`. Первый — успешный. Второй — бросает в catch. `console.log('done')` — после блока try/catch, выполняется всегда.

</details>

---

### Задача 22

```js
async function run() {
  try {
    await Promise.reject('error');
  } catch (e) {
    console.log('caught');
    return 'from catch';
  } finally {
    console.log('finally');
  }
}
run().then(v => console.log('result:', v));
```

<details>
<summary>Ответ</summary>

```
caught
finally
result: from catch
```

`finally` выполняется **всегда** — и при успехе, и при ошибке, и при `return` из `catch`. `return` в `catch` не отменяет `finally`, но и не перезаписывается им (значение `'from catch'` сохраняется).

</details>

## Блок 6 — Комбинаторы: all / race / allSettled / any

### Задача 23

```js
Promise.all([
  new Promise(r => setTimeout(() => r('slow'), 100)),
  Promise.resolve('fast'),
]).then(([a, b]) => console.log(a, b));
```

<details>
<summary>Ответ</summary>

```
slow fast
```

`Promise.all` ждёт **все** Promise и возвращает массив в **порядке входного массива**, независимо от порядка выполнения.

</details>

---

### Задача 24

```js
Promise.all([
  Promise.resolve(1),
  Promise.reject('error'),
  Promise.resolve(3),
])
  .then(r => console.log('ok:', r))
  .catch(e => console.log('fail:', e));
```

<details>
<summary>Ответ</summary>

```
fail: error
```

`Promise.all` завершается с ошибкой, как только **любой** Promise отклонён. Остальные результаты игнорируются.

</details>

---

### Задача 25

```js
Promise.race([
  new Promise(r => setTimeout(() => r('slow'), 100)),
  new Promise(r => setTimeout(() => r('fast'), 10)),
  Promise.reject('immediate'),
])
  .then(v => console.log('won:', v))
  .catch(e => console.log('rejected:', e));
```

<details>
<summary>Ответ</summary>

```
rejected: immediate
```

`Promise.reject('immediate')` уже отклонён в момент создания — выигрывает гонку. `Promise.race` разрешается/отклоняется по **первому** завершившемуся Promise, будь то успех или ошибка.

</details>

---

### Задача 26

```js
Promise.allSettled([
  Promise.resolve('ok'),
  Promise.reject('fail'),
  Promise.resolve('also ok'),
]).then(results => {
  console.log(results.length);
  console.log(results[1].status, results[1].reason);
});
```

<details>
<summary>Ответ</summary>

```
3
rejected fail
```

`Promise.allSettled` **никогда не отклоняется** — ждёт все Promise и возвращает массив объектов `{ status: 'fulfilled'|'rejected', value|reason }`.

</details>

---

### Задача 27

```js
Promise.any([
  Promise.reject('e1'),
  Promise.resolve('winner'),
  Promise.reject('e2'),
])
  .then(v => console.log(v))
  .catch(() => console.log('all failed'));
```

<details>
<summary>Ответ</summary>

```
winner
```

`Promise.any` разрешается первым **успешным** Promise, игнорируя отклонения. Отклоняется только если **все** Promise отклонены (тогда `AggregateError`).

</details>

## Блок 7 — Сложные цепочки

### Задача 28

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => {
  console.log('3');
  setTimeout(() => console.log('4'), 0);
});
console.log('5');
```

<details>
<summary>Ответ</summary>

```
1
5
3
2
4
```

Синхронно: `1`, `5`. Микрозадача: `3` + добавляет в очередь второй таймер. Макрозадача №1: `2`. Макрозадача №2: `4`.

</details>

---

### Задача 29

```js
async function foo() {
  console.log('foo: start');
  await Promise.resolve();
  console.log('foo: end');
}
async function bar() {
  console.log('bar: start');
  await Promise.resolve();
  console.log('bar: end');
}
console.log('before');
foo();
bar();
console.log('after');
```

<details>
<summary>Ответ</summary>

```
before
foo: start
bar: start
after
foo: end
bar: end
```

`foo` и `bar` запускаются синхронно по очереди, каждая доходит до `await` и приостанавливается. После синхронного кода микрозадачи выполняются в порядке постановки в очередь.

</details>

---

### Задача 30

```js
Promise.resolve()
  .then(() => console.log('micro 1'))
  .then(() => console.log('micro 2'))
  .then(() => console.log('micro 3'));

setTimeout(() => console.log('macro'), 0);
```

<details>
<summary>Ответ</summary>

```
micro 1
micro 2
micro 3
macro
```

Ключевое: очередь микрозадач опустошается **полностью** перед тем, как Event Loop берёт следующую макрозадачу. Каждый `.then` добавляет новую микрозадачу — они все выполняются до `setTimeout`.

</details>

## Шпаргалка — порядок выполнения

```
1. Синхронный код (Call Stack)
2. Очередь микрозадач (Promise.then / .catch / .finally, queueMicrotask, await)
   └── после каждой макрозадачи — снова полностью опустошается
3. Одна макрозадача (setTimeout / setInterval / события)
4. → снова п.2
```
